# API 概览

本栏目将作为 BodyOS SDK 的接口参考。下方现有契约属于预览概念，不是已经验证的 wheel 接口文档。真实签名、软件包名称及支持的传输方式须与实际发布版本核对。

Open Unit 的 API 范围预计会逐步扩展，但应始终围绕几个稳定概念组织：

- **会话管理**：请求和跟踪命令权限
- **控制接口**：提交受边界约束的命令
- **遥测接口**：获取设备状态及实验数据
- **系统接口**：检查健康状态、故障及配置

## 当前文档编写思路

本节使用贴近实际的占位示例，不假定最终接口参考已经存在。

这是有意为之。对于早期平台团队，清晰的契约与统一命名，比基于猜测自动生成的接口参考更有价值。

## 预期 API 特征

最终 API 应提供：

- 带版本的结构定义（schema）
- 可被机器读取的错误响应
- 数值的明确单位
- 不依赖具体传输方式的概念，可映射到 gRPC、REST、ROS 2 或设备本地 RPC 层

## API 成熟度模型

| 阶段 | 预期 |
| --- | --- |
| Preview（预览） | 概念及消息结构可能快速变化 |
| Beta（测试） | 开始重视向后兼容目标 |
| Stable（稳定） | 执行版本管理及弃用策略 |
