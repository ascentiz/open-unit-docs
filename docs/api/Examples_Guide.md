# 官方示例代码详解 (Examples)

返回主目录：[README](./README.md)

本指南详细讲解 `bin/`（C++）和 `python/` 目录下的 4 个官方 Demo，帮助您快速理解 BodyOS SDK 的最佳实践与安全机制。

> **📌 通用提示**：
> *   所有 C++ 示例在编译后会被输出到 `bin/` 目录。
> *   所有 Python 示例依赖 `bodyos` 包（位于 `python/bodyos`），请在 `python` 目录下运行，或将其添加到 `PYTHONPATH`。
> *   运行任何控制类 Demo（如助力、电机控制）前，请确保底层物理硬件（CM5、CAN 总线、控制板）已上电并且通讯正常。

---

## 1. `sensor_read_record` (传感器读取与异步录制)

**功能**：演示如何申请只读模式（`DATA_COLLECT`），高频拉取传感器数据，并利用后台线程写入压缩的 `.csv.gz`。适合做数据采集与离线算法分析。

### 运行方式
```bash
# C++ 版本
./bin/sensor_read_record -t 10 -i 100

# Python 版本
python3 sensor_read_record.py -t 10 -i 100
```
*   `-t 10`: 运行 10 秒后自动退出。
*   `-i 100`: 录制间隔为 100ms（内部利用 `seq` 去重，避免重复写相同帧）。

### 核心逻辑与安全机制
1.  **模式申请**：脚本首先会申请 `DATA_COLLECT` 模式。这是**只读模式**，底层会强制切断一切电机的使能指令，保证硬件绝对安全。
2.  **数据去重**：主循环 1ms 轮询一次，但只有发现 `sensors.seq` 发生变化时，才视为新数据。这保证了 100Hz 的硬件推流不会被重复记录。
3.  **异步落盘**：`client.record_sensors(sensors)` 操作仅将数据放入内存队列（微秒级），真正的磁盘 IO 与 Gzip 压缩在后台线程中完成，绝不卡顿采集主循环。
4.  **优雅退出**：在 Python 版本中，退出时增加了短暂的 `sleep(500ms)`，等待后台的 Gzip 压缩线程完成最终的 `.csv` 到 `.csv.gz` 转换。

## 2. `body_assist_control` (BLE 助力模式控制)

**功能**：控制 BLE 控制盒的助力模式（EASE / ACC / TRAIN）、运动场景与助力挡位。这是用户交互最常用的功能之一。

### 运行方式
```bash
# C++ (切换为 EASE 模式，场景 2，挡位 50%)
./bin/body_assist_control -m 0 -s 2 -l 50

# Python
python3 body_assist_control.py -m 0 -s 2 -l 50
```
*   `-m` (mode): 0=EASE, 1=ACC, 2=TRAIN
*   `-s` (scene): 运动场景序号（不同模式有不同范围限制，可通过-h/--help查看详情）
*   `-l` (level): 助力挡位 0~100%
*   `-p` (pause): 0=运行，1=暂停
*   `-r` (read): 仅读取当前状态并退出

### 核心逻辑与安全机制
1.  **权限接管**：脚本启动后，首先会检测 `gait_mode`，若不为 0（即底层未由算力盒接管），会先强制切换并**回读验证**，确保权限正确。
2.  **增量更新**：使用 `update_ble_assist` 接口。SDK 内部会先通过后台推流请求一次当前心跳作为基准，**仅覆盖你传入的 `-m/-s/-l` 参数**，其余参数（如自动识别开关、其他场景位）保留原值，防止意外清零。
3.  **参数合法性校验**：在将指令发给 daemon 之前，SDK 会拦截非法的场景值（如 TRAIN 模式下传入场景 5）和超出 100% 的挡位。

## 3. `body_expert_control` (专家参数调整)

**功能**：微调助力算法底层的物理参数（如平滑度、基础助力、步频、响应等级等）。提供给高级调试人员使用。

### 运行方式
```bash
# C++ (修改平滑系数为 50，基础助力 10)
./bin/body_expert_control --smooth 50 --base 10

# Python
python3 body_expert_control.py --smooth 50 --base 10
```
*   `-r` (read): 仅从缓存读取全量专家参数并打印。
*   `--mode`, `--smooth`, `--base`, `--speed`, `--freq`, `--resp`, `--coeff`: 分别修改不同的物理参数。

### 核心逻辑与安全机制
1.  **静默同步机制**：专家模式参数多达十几个（分为 Easy 和 Acc 两套）。如果用户只传入 `--smooth`，直接下发会导致其他十几个参数被清零。SDK 内部的 `update_ble_expert` 会在首次调用时，先静默执行 `BLE_GET_EXPERT` 获取设备的全量参数作为基准缓存，随后仅替换传入的参数，最后一次性打包下发。
2.  **边界检查**：不同参数的允许范围不同（如系数是 `-20~20`，其他是 `-200~200`），SDK 会提前拦截越界值。

## 4. `direct_motor_control` (底层电机直接控制)

**功能**：绕过所有步态算法，直接向 4 个驱动器发送力矩、速度或位置指令。包含软硬件级别的极限安全保护，常用于电机测试或自研算法。

### 运行方式
```bash
# C++ (力矩模式，控制 4 个电机，输出 1.0 Nm)
./bin/direct_motor_control -m 0 -n 0x0F -v 1.0

# Python
python3 direct_motor_control.py -m 0 -n 0x0F -v 1.0
```
*   `-m`: 0=力矩，1=速度，2=位置
*   `-n`: 节点掩码 (15 或 0x0F 代表全部四个电机)
*   `-v`: 目标值
*   `-r`: 仅读取当前控制模式并退出

### 核心逻辑与安全机制
1.  **强制接管**：先申请 `USER_CONTROL` 模式，然后调用 `set_gait_mode(1)` 踢掉底层算法，并**回读验证**确认接管成功后才继续。
2.  **物理安全限幅**：在把值发送给 SDK 前，代码强制进行安全范围限制（力矩 ±2.0Nm，速度 ±40 turn/s，位置 ±32 圈），并在终端提示。
3.  **防卡死退出（极其重要）**：
    *   **C++ 端**：退出时调用 `send_raw`（单向发送）下发停止指令，因为不需要等 ACK，不会卡死。
    *   **Python 端**：主线程将控制循环放入独立的后台线程。当用户按下 `Ctrl+C` 时，主线程立即捕获信号，将 `g_running` 置为 `False`。在 `finally` 块中，主线程**绕过常规封装**，直接向 Socket 写入 0 速度和失能指令（`wait_reply=False`），并设置 0.2s 的 Socket 超时。哪怕 CAN 总线被物理堵死，Python 也能瞬间强行断开连接退出，绝对不会假死。
