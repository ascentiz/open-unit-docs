# 平台边界

Exoskeleton Unit 与 Open Unit 之间的边界是一份控制契约，而不仅是一张接线图。

## Exoskeleton Unit

Exoskeleton Unit 负责必须保持确定性且在设备本地执行的行为：

- 执行器驱动及对时序敏感的控制环
- 安全运行所需的设备状态转换
- 关节、电流、扭矩、温度及通信限制的执行
- 上层软件停滞或断开连接时的看门狗行为

简而言之，Exoskeleton Unit 是系统保护用户与硬件的层级。

## Open Unit

Open Unit 负责需要更灵活计算环境的行为：

- 高层控制策略
- 意图估计与传感器融合
- 实验协议与应用逻辑
- 遥测聚合、存储及转发
- 开发者工具、远程操作及集成服务

因此，Open Unit 适合科研人员与合作伙伴开展开发，而安全关键约束不应依赖无法保证确定性执行的用户空间代码。

## 命令流程

典型命令路径如下：

1. Open Unit 上的应用计算请求动作。
2. 请求携带会话与模式上下文进行封装。
3. Exoskeleton Unit 根据当前状态及配置限制验证请求。
4. Exoskeleton Unit 接受、修改或拒绝请求。
5. 遥测与状态反馈返回 Open Unit，用于日志记录及自适应处理。

## 设计规则

架构应长期保持以下规则：

- 任何应用都不应依赖绕过 Exoskeleton Unit 安全层
- Open Unit 连接丢失时，Exoskeleton Unit 应降级至安全行为
- 命令接受必须始终考虑当前状态
- 故障报告应可被机器读取，也应对操作人员可见

## 对开发者集成的影响

为 Open Unit 编写软件时，应假定底层拥有最终决定权。代码需要处理：

- 被拒绝的命令
- 被限幅的命令
- 过期或暂停的会话
- 暂时不可用的传感器
- 明确的解除使能或急停状态转换
