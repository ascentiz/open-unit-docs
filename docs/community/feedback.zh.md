# 问题反馈

结构化且可执行的反馈最有价值。

## 问题类型

提交反馈时，请使用以下分类：

| 类型 | 应包含的内容 |
| --- | --- |
| 文档缺失 | 页面 URL、缺失细节及尝试完成的任务 |
| API 反馈 | 当前契约、预期行为及集成限制 |
| 缺陷报告 | 复现步骤、日志、版本及观察到的影响 |
| 安全问题 | 确切条件、受影响流程及已采取的即时缓解措施 |
| 科研咨询 | 研究目标、技术需求及预期时间安排 |

## 建议流程

1. 搜索已有 Issue 或讨论。
2. 创建新 Issue，在有帮助时附上日志、截图或跟踪记录。
3. 明确标记安全相关问题，避免将其埋在一般讨论中。
4. 科研合作请求应首先说明实验室背景及实验目标。

## 响应预期

作为早期平台，不同主题的响应时间可能不同：

- 文档修正通常较为直接
- API 或架构请求可能需要产品与安全评审
- 科研请求通常更适合提供简短技术摘要，而非一般性咨询

## 最低有效缺陷报告

请包含：

- Open Unit 软件版本
- Exoskeleton Unit 固件版本
- 尝试执行的确切命令或流程
- 观察到的状态及故障输出
- 是否可以重复出现
