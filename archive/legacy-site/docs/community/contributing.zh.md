# 贡献指南

本项目旨在随着平台成熟保持易于扩展。

## 贡献流程

1. 创建或查看说明本次修改的 Issue。
2. 为更新创建短期分支。
3. 保持修改范围集中，技术表达明确。
4. 提交 Pull Request 前，执行本地文档构建。
5. 如果修改涉及架构、安全或 API 行为，请相关平台负责人评审。

## 文档规范

贡献文档时：

- 优先使用精确技术语言，而非宣传性表述
- 接口未定型时，明确说明假设
- 在相关内容中注明单位、状态及失败行为
- 保持示例简短，便于快速评审

## Pull Request 检查清单

提交之前，请确认：

- `mkdocs build --strict` 构建成功
- 新增页面时已更新导航
- 链接可正确解析
- 占位内容已明确标注

## 高敏感度修改

涉及以下领域的修改应接受额外评审：

- 安全行为
- 状态机
- 命令权限
- 设备限制
- 可能影响研究执行的科研指南
